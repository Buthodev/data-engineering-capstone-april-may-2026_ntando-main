What We Are Cooking

A South African retail bank has one messy flat export covering client details, product enrollments, CRM contact history, and transactions, all mixed into a single file. Nobody has ever built a proper warehouse for it, and reporting today is a person manually pulling spreadsheets.

Your job is to build the first version of a Customer 360 data warehouse: a star schema in SQL Server, loaded by a repeatable SSIS pipeline, that a BI team could plug straight into Power BI or Tableau.

This is a skills exam, not a memory test. You are expected to:

  • Profile a messy, denormalized source file and work out what is actually in it
  • Separate the different entities and event types hiding inside one extract, and design sensible keys for each
  • Design a dimensional model: grain, dimensions, facts, and how they relate
  • Build an SSIS package that lands, splits, and transforms the data
  • Write SQL against your model to answer real business questions
  • Explain and justify every decision you made

There is no single correct schema. Two students can both pass with different, well justified designs.

How To Submit

  1. Fork the repository to your own GitHub account, or create a branch if you already have write access
  2. Clone your fork locally
  3. Create a branch named after you, for example intern/thabo-m
  4. Commit as you go, in small steps, with clear messages, not one giant final commit
  5. Push your branch
  6. Open a pull request against main when ready for review, with your data quality note and a short summary of your design decisions in the description
No late submissions without prior arrangement. Read the full brief in the repository before you start.
